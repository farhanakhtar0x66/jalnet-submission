# JalNet architecture and provider boundaries

The intended production path remains Expo native development build → Amazon Location map assets directly → Cognito-protected HTTP API → separate TypeScript Lambda services → DynamoDB/H3, private S3 and SQS → configurable Bedrock Nova. Amazon Location Routes runs in the backend. CDK TypeScript is the only infrastructure framework.

`services/core/ports.ts` defines repository, evidence, analysis, routing and report authorization boundaries. The same `Application` executes domain rules with either local or AWS adapters. Cloud Lambda entry points always construct AWS adapters; they never accept demo tokens or silently fall back to local storage. `scripts/dev-server.ts` starts the localhost composition in `services/local/server.ts`, which retains the existing explicitly named LOCAL_DEMO identities.

The local composition requires real Cedar 4.13.0 authorization before private-report reads, upload grants, completion and confirmation. `ownedReport()` derives ownership from the persisted report and retains its original owner check. Initialization/evaluation failure never falls back to legacy authorization. Cedar provides no authentication, roles or new product features. Existing AWS composition is unchanged and does not load Cedar; Lambda WASM packaging/live proof remains a separate unverified future gate. See [Cedar boundary audit](CEDAR_AUTHORIZATION.md).

The mobile app uses TanStack Query for API state and invalidates events, risks and profile after submission. Zustand contains only map layer, pin, selection and accuracy UI state. SQLite and an application-private file retain the pending capture across app restarts. A separate SQLite cache retains validated events/routes for at most 24 hours, scoped by a hash of the authenticated account scope. Only transport failures allow a cache read; authorization, configuration and schema errors never do. Offline results show their timestamp, suppress current-risk claims, and offer connection retry. No background route tracking is requested.

Public incident responses omit identities, internal vote/supporter lists, evidence hashes and S3 keys. Private-property reports cannot enter public viewport results or public-route warnings. Original evidence is never a public map thumbnail. Current events use logical expiry; canonical history is retained instead of DynamoDB TTL deletion.

Upload completion uses `POST /v1/reports` with `action: UPLOAD_COMPLETE`. The server reads the owned object, checks bytes/type and bounded JPEG decoding, then transitions to ANALYZING. In AWS, the API queues the report ID and the worker validates Nova output with at most one retry; failure preserves NEEDS_CONFIRMATION for manual classification. No AI output publishes an event by itself.

Report confirmation atomically writes the final report, incident, immutable awards and conditional primary-key guards. Ledger uniqueness is enforced on primary keys, not a GSI. Daily provisional caps and copied-image hashes use the same transaction. Event revisions guard concurrent independent votes. Two independent photo reports allow community corroboration; votes alone never generate meaningful points. One independent cleared vote produces MONITORING, two produce RESOLVED. These are prototype policies, not scientific certainty or authority verification.

Location Routes V2 Simple LineString is validated then explicitly converted to Google encoded polyline for saved-route storage. Intersection checks every segment against incident semantic radius plus corridor width; freshness/confidence/severity influence warnings. An absence of intersecting reports does not establish route safety.

LOCAL/DEMO adapters persist private data under ignored `.local-data`, offer short-lived localhost upload grants, return an uncertain/manual assessment without interpreting images, and generate straight-line route corridors. No LocalStack, fake AWS credentials or architecture replacement is introduced. This mode does not meet the live P0 Definition of Done.

Remaining reliability limits: cross-incident fusion uses an eventually consistent H3 GSI; concurrent creation can conservatively leave separate incidents. A transactional 90-second analysis lease bounds concurrent model work; completed report replays return without invocation. A local concurrent-worker test passes. Live SQS duplicate-delivery, crash/retry and model-cost proof remains unverified. Upload quotas are transactional (five grants per report, 100 per user/day); draft creation is capped at 20/day, route calculations at 30/day, and provisional awards at 10 droplets/day. A warm-process route cache lasts five minutes and holds at most 200 owner-scoped entries; cold Lambda processes do not share it. DynamoDB candidate work is bounded to 512 cells, eight concurrent queries, 100 records/page, five pages/cell and 1,000 unique candidates, with an error on overflow. Public results are filtered/ranked before the 200-card cap. Broad GPS-spoof resistance, token refresh/revocation, a review-authorized reversal workflow and real operational budgets/alarms remain incomplete. Five-route enforcement is a pre-write check and still needs a transactional concurrent-save cap. Long routes can exceed the intentionally bounded urban viewport query budget.

Confirmation logically passes through SUBMITTED and writes ACCEPTED/MERGED in one atomic transaction; no intermediate externally persisted SUBMITTED state is exposed. The existing state-machine helper documents legal conceptual transitions. Evidence hashes are checked again before assessment and confirmation to reject changed uploads; S3 signed-URL replay/version behavior still needs live testing.
